# 已知问题与开发范围

本文件说明代码的能力边界，不包含真实批次、运行数据或实验成绩。

## 尚未解决

1. **QEMU 环境准备**：`qemu-startup` 和 `qemu-alpine-ssh` 的 Debian 软件源可能因 Release 元数据有效期问题拒绝更新。平台保持官方测试脚本不变；此类失败应记为基础设施异常，不能解释为模型答错。
2. **长轨迹监督**：规范化证据仍有输入长度边界，尚未实现完善的分段监督。监督输出也受模型预算影响，失败时不会自动创建纠错 Attempt。
3. **跨主机与部署**：主要开发环境为 Windows + Docker Linux 容器。Linux 路径已经兼容，但整条真实模型链路仍需在目标部署环境验证。当前 Portal 不提供生产级身份认证、分布式调度或共享 Artifact 存储。

## 已具备

- 超时及异常退出后的容器进程停止确认，无法确认停止时禁止评分。
- Harbor 正常清理后再次核对 Trial 容器、网络和卷；服务重启时回收本数据目录对应的遗留资源，预构建镜像继续缓存。
- 原始 reward 与可采信分数分开记录，官方 CTRF 和工具调用时间核查。
- 根据 Harbor 实际阶段区分环境准备、Agent 安装、Agent 执行和官方评分异常。
- DSH 使用显式选项结束符传递题面，支持以连字符开头的官方任务。
- 破损 JSONL 行记录与其余轨迹保留。
- 任务内容、执行运行包及适配文件的摘要校验。
- 大型详情 JSON 的 Worker 处理与轨迹分段展示。
- 独立监督、人工审核及保留历史的纠错尝试。

正常超时代表预算内未完成；终止修复保障到时停止，不保证任务一定通过。评测代码存在已知适配问题时，应先排除平台原因，再解释模型能力。

## 代码交付说明

此分支在当前开发源码基础上，将用户目录改为项目相对路径或环境变量；默认监督配置与当前配置版本对齐，并让 Terminal-Bench 导入器记录全部适配文件。没有携带或回填本机实验数据库。

修改执行代码后应创建新快照再运行，避免已有快照与当前文件摘要不一致。旧的已完成运行结果不通过修改数据库的方式静默改写。
